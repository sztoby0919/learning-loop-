# Mode contracts

Read the section for the active mode plus `Mode switching`. Match the learner's language and level. Prefer examples, retrieval, and small practice tasks over long lectures.

## `ladder`: five-level learning map

Build exactly five progressive levels: complete beginner, basic understanding, practical user, problem solver, confident practitioner. For each level include:

1. level name;
2. what to understand;
3. observable mastery state;
4. core concepts or skills;
5. advancement milestone;
6. hands-on exercise or mini-project;
7. common learner mistakes;
8. one self-test question.

Order prerequisites before advanced applications. Tailor milestones to the stated goal and practice conditions.

## `20-hour-plan`: high-leverage first pass

Default to ten two-hour units, but scale unit count or duration to the learner's actual budget. First identify the smallest set of concepts and skills likely to unlock most practical results; explain their connections without claiming a literal guaranteed 80/20 ratio.

Each unit contains a learning objective, core concepts, hands-on exercise, one verified beginner-friendly resource, expected observable outcome, and five retrieval questions. Finish with one integrative project and a concrete acceptance checklist. Do not imply that twenty hours produces expert mastery.

## `quiz`: active-recall boundary test

- Ask exactly one question, then stop and wait. Never show later questions or the answer in advance.
- Default to ten questions: 1–3 beginner, 4–6 intermediate, 7–8 advanced, 9–10 expert. Adapt difficulty to observed performance while preserving increasing challenge.
- After each sufficient answer: score out of 10, identify what is correct, name precise gaps, and re-explain only missed material in simple language.
- For a weak or ambiguous answer, ask one focused follow-up before scoring or advancing. A follow-up does not count as the next numbered question; score the original question once after the follow-up.
- At the end provide total/average performance, strongest and weakest areas, and a short review plan. Offer a queue of five challenge topics, not five full questions. If the learner continues, turn the queue into questions one at a time under the same wait-before-next rule.

Judge reasoning and transfer, not wording similarity. Accept correct explanations expressed differently.

## `cheat-sheet`: five-minute compression

Create a one-page-equivalent, scan-friendly artifact containing: plain-language definition; essential concepts, rules, formulas, or steps; one useful diagram/table/mental model when it materially clarifies structure; three to five concrete applications; common confusions; a pre-use checklist; and five rapid recall questions without answers immediately adjacent.

Compress structure, not correctness. If the topic cannot fit honestly on one page, label the covered slice.

## `resources`: signal over collection

Recommend five resources unless the learner requests another number. For each include name and direct canonical link, type, why it earns time, the exact gap it covers, best-fit learner, difficulty, an efficient usage method, and what not to spend time on. Rank them in use order and build a seven-day path using only those resources.

Browse before recommending. Open enough canonical pages to confirm identity, accessibility, current edition/version where relevant, and claimed coverage. Prefer free or beginner-friendly material when quality is comparable. A paid resource must be labeled. Do not use search-result pages as citations.

## `feynman`: explain, diagnose, repair, repeat

If the learner has not attempted an explanation, give a short child-friendly explanation using plain words, one real example, and a useful analogy, then ask them to teach it back.

For each learner explanation:

1. identify what is correct;
2. list every material error, ambiguity, and missing link;
3. re-teach only those gaps with examples;
4. ask for a cleaner explanation in the learner's own words;
5. stop and wait.

Repeat until the explanation is simple, accurate, and complete for the agreed level. Do not accept memorized wording without understanding. Only after convergence provide a clean final explanation suitable for notes.

## Mode switching

Switch modes when evidence warrants it: a failed quiz answer can enter a focused Feynman repair; a stable explanation can become a cheat sheet; a milestone completion can trigger a quiz. Tell the learner why the switch helps. A nested Feynman repair still requires the learner to re-explain and a subsequent gap check; return to the quiz only after the current question's gap has converged. Return to the prior mode afterward unless the learner chooses a new goal.
