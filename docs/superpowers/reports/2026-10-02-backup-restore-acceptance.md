# ZIP 备份与恢复验收记录

日期：2026-10-02–03。当前阶段：原 ZIP 批次审查及修复历史保留如下；Windows 原生补充批次的一次独立审查、作者两项修复与约定的本机 Windows 单服务验收已完成。限定平台及威胁边界，不宣称全面安全审计。默认8worker测试稳定性为延期次要事项。

## 已实现

- 设置页按单课程或全部课程预览、下载 ZIP；JSON 导出不变。
- 白名单课程文件、sessions Markdown、受管原课件，以及版本/长度/SHA-256 manifest；不读取外部资源、密钥、配置、草稿或缓存。
- 基于 yauzl 公开逐条、流式读取 API 检查原始条目、重复/大小写冲突、路径、链接、local/central header、CRC、实际长度与上限；不使用 JSZip 解码作为安全保证。
- 校验后恢复预览，刷新/重启继续、固定 24 小时到期、主动取消、启动/每小时清理；确认恢复为全新课程，不覆盖原课程，同一预览确认幂等。
- 结构化更新 metadata 关联及资源表内部来源 URL；正文、原课件、日期、分数不重写。恢复会话增加 evidenceCourseId，保持原错题计算 ID 和再练关联，包括再次备份恢复。
- publishing 日志在任何课程发布前持久化，committed 原子状态替换是提交点。整批失败撤销新增配置和缓存，将本事务拥有的发布目录移回暂存；启动先协调，再自动发现，未决课程排除。已提交后 watcher 失败不删除课程。
- 准备阶段中断可清理已验证暂存目录；坏/不明事务记录保留、fail closed，不猜测删除用户数据。只支持单服务实例。

## 取舍与未验证事项

使用当前工作区和手动 ledger，保留所有原改动；没有 commit/push，记录只在本地。既有 JSZip 调整到运行依赖只用于生成；新增 yauzl/type 安装已获用户同意，ignore-scripts。运行依赖体积相应增加。

## Windows 原生补充批次（2026-10-02–03）

上述“竞态尚未修复”是原批次的历史结论，不是原生补充实现的结论。用户已接受 Windows-only、本地单服务、辅助程序不可用时停止 ZIP 而不停止健康课程/普通导入/AI 的边界。

- 系统 Windows PowerShell/.NET 辅助进程逐级持有目录句柄；实际读取、独占写入、发布、原子状态替换及所有权清理均在该进程内完成，禁止 Node 普通路径 IO 回退。
- 拒绝 UNC/reparse/多硬链接；新建输出未完成时保持 OS delete-pending，真实 kill helper 后不继续操作；全树先核验后按句柄清理，不沿子 junction 删除外部内容。
- 固定命令白名单、64 KiB 块、128 KiB 帧、16 活动 streams、4400 清理元数据句柄、15 秒操作预算。正常闲置 worker 退休后可重建，异常退出则需重启服务。无需新增工具链、提升权限或更改系统策略。
- 解压结果的 manifest/Markdown/来源在复制前再次核对当前 bytes 的 SHA/长度；真实更改三类文件的测试先失败后通过。批量登记使用已核验 Markdown 快照，避免发布后通过普通路径再读取。
- 不可用或事务无法核验时，`restored-` 自动发现暂缓，原目录保留；坏记录不猜测归属。单独验证健康课程浏览与普通导入仍可运行。

串行本机复验：`npm test` exit 0，64 files、489 passed / 6 skipped，119.60 秒；端口隔离 2/2；`npm run build` exit 0（Vite 1.74 秒）；`npm run test:e2e` exit 0，三设备 45/45，1.2 分钟。6 个跳过是链接权限限制，并不等于那些环境场景已通过。原生事务独立 9/9，含 2200 文件双副本清理；真实 helper 崩溃后由独立 Node 进程回滚、再次确认通过。HTTP ZIP 超限 250 MiB 文案已修复，接口用受控 MulterError 注入验证，并非真实 251 MiB 请求性能测试。

### 补充独立审查与一次作者修复

一次 fresh-context 只读审查结论为不通过：Critical 空父目录原位变成 junction 后，绝对路径创建/发布仍可能越界；Important finishWrite 失败后提前 ended，导致 finally abort 无效。无 Minor。审查员没有执行利用或重跑全套；随后主代理用真实 FSCTL 注入复现目录创建、文件创建和发布三个窗口，外部临时哨兵目录确实新增条目，3 RED；提交失败边界保留真实 lease，partial 文件未删除，1 RED。

修复使用 `NtCreateFile` 的 RootDirectory+单级名称逐级打开/创建，不用拒绝共享写的未经验证假设。枚举改为 `NtQueryDirectoryFile` 的实际目录句柄，发布目标通过 `NtSetInformationFile`/FileRenameInformation 的 RootDirectory 绑定；Win32 wrapper 相对重命名实测报87后未回退绝对路径。提交失败主动终止实际 lease，finally 释放祖先句柄；不能确认 abort 时终止 worker，保留首次错误。

定向原生三文件25/25通过；测试辅助程序副本额外注入一次真实 C# flush 失败，验证部分文件清除、父目录可重命名、16个写入额度可复用、同一 worker 下一次实际写入和读取成功。此加强测试为实现后的验收，不冒称单独RED。生产没有脚本覆盖入口，全部注入及清理只在自建临时目录。不重复分派审查；审查发现由作者回归验证，不冒称修复后再次获得独立批准。
