## 独立审查与修复

## 测试调试记录

完整并行回归出现后台落盘状态未在默认 1 秒等待内完成，模块单独复跑通过；单个多轮测试也超过默认 5 秒总时限。最终给同类异步测试明确条件等待 5 秒、多轮生命周期总时限 15 秒，并限制 Vitest `maxWorkers: 4`，全量回归通过（约 38 秒）。这只是测试资源/等待预算，产品 90 秒超时不变；不以延长等待代替性能测试。

ZIP 能力验证夹具原用 Buffer 被前端 tsconfig 纳入，构建报错；使用 Uint8Array/DataView 编码小型对抗夹具后构建通过，不扩大前端 Node 类型。夹具不是生产 ZIP 解压器。

## 取舍与未完成项

- 沿用当前 main 工作区，不创建工作树、不提交；成本是旧修改与新修改共享未提交状态。
- 无 Git Bash，使用 apply_patch 维护同格式本地执行记录；成本是记录需人工核对。
- 共享类型迁移暂保留 optional 字段，新生成与持久化严格校验；不能把旧调用的可选类型理解为新数据可缺失 ID。
- 初始完整测试与新增测试重叠，不宣称有干净实现前基线；最终绿色回归才是交付证据。
- 保存期间冻结阶段新增/删除/排序，文本仍可编辑；成本是结构操作要等保存结束。
- 沿用第一批工作区与手动记录的裁定；没有第二批额外工作树或实现代理。
- ZIP 暂不交付，现有 JSZip 实测会覆盖重复原条目并规范化恶意路径，不能满足原始条目安全校验。
- 真实 MoMA 未调用，无法保证实际模型输出质量或取消后提供商停止计费。
- 仅支持本地单服务实例；不能承诺多实例目录互斥。
- 专项审查限本次两批，其他旧业务虽运行回归，也不是完整安全审计。
- 无提交历史记录本轮任务，因此保留 `.superpowers/sdd/` ledger；成本是任务记录仅本地，需备份。
- 测试并发和等待预算明确化，以较长全量执行时间换取资源可控，不把预算当性能指标。
