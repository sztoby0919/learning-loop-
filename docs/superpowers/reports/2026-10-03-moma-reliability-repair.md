日期：2026-10-03（Asia/Shanghai）。结论：本轮已复现的本地缺陷已修复，最新真实 MoMA 浏览器流程 **7/7 通过**；完整单元/接口回归 **508 通过、6 跳过**，端口隔离测试 **2/2 通过**，三设备隔离浏览器回归 **12/12 通过**，类型检查与生产构建通过。

这份报告是修复后的结果；此前 `2026-10-03-moma-browser-acceptance.md` 保留了修复前失败，不能将两个时间点的结果混用。

## 修复内容与证据

| 问题 | 根因及修复 | 验证 |
| --- | --- | --- |
| 诊断超时仍继续请求 | AiService 原先 30 秒 Promise.race，Provider 自己等待 90 秒，且服务超时不传播取消。统一为 90 秒操作总期限，信号传入 Provider，清理成功/失败定时器 | 回归测试先失败、修复后通过；底层 fetch 被取消且没有超时自动重试 |
| 临时服务错误直接失败 | HTTP 500 等原先没有受控恢复路径。仅临时网络故障及 HTTP 500/502/503/504 最多重试一次，等待和重试都计入总期限；超时、鉴权、额度和格式错误不重试 | 核验一次 500 后成功、鉴权一次请求、无效 JSON 一次请求 |
| 具体失败原因被隐藏 | 诊断错误处理、练习模块包装丢失原始安全错误。引入 AiRequestError，接口返回安全的超时/网络/鉴权提示，练习模块保留该错误 | 诊断和练习超时接口返回 504，提示包含超时；不暴露 Key 或上游正文 |
| 读取正文断连误判为格式错误 | 原 JSON catch 区分不足。仅 SyntaxError 是不可重试格式问题，正文网络中断进入有界恢复 | TypeError 正文断连后恢复，SyntaxError 不重试 |
| HTTP 200 缺少模型文本变成普通 500 | callApi 原先抛普通 Error。改为 AiResponseFormatError，由现有接口处理器返回安全 502 | Provider 及真实接口链路回归测试通过 |
| 重试等待中取消泄露内部原因 | 延迟的取消异常绕过网络分类。统一处理为安全的取消错误，释放定时器和监听器，不再发送请求 | 回归测试先看到原始取消原因，修复后 499，调用次数保持 1 |
| ZIP 文件辅助进程闲置后异常退出 | 正常 ENOENT/EEXIST 失败清掉空闲定时器却不重新安排，健康进程被 15 秒看门狗结束，后续操作永久失败。正常错误也安排空闲回收；实际崩溃依旧 fail-closed，不降级为不安全文件操作 | 原生测试先复现“Windows 文件辅助进程已退出”；修复后缺失文件错误、16 秒等待、后续写入都通过 |

AI 请求发送明确的 `stream: false` 并拒绝重定向，避免接口协议含糊和意外跨地址传递认证。草稿重试使用同一份用户已同意的摘录，不扩大文本范围；页面和 README 已解释最多一次临时错误重试及费用风险。

## 使用与边界

后台普通 start 模式需要重启以加载服务端修复。在项目根目录终端 Ctrl+C 后运行 `npm run dashboard`，再刷新网页。已完成生产构建，不要求用户再构建。未提交、未 push。

真实流程通过证明这次修复可用，但不保证第三方提供商永远没有 HTTP 500 或超时。排查中观察到一次 HTTP 500、后续成功，以及一次 90 秒无响应；提供商内部原因未确认。本地现在会有界等待、取消与有限恢复，并显示具体原因，不会伪造题目或学习证据。没有声称完成长教材性能、高并发稳定性或三设备真实付费模型验收。

关键知识点：超时必须传播到实际网络请求；重试应区分临时故障和永久错误；辅助进程正常空闲回收与异常崩溃是不同状态。容易踩坑：HTTP 响应头回来不表示正文生成完成；Promise.race 不会自动取消另一个 Promise；浏览器 PDF 查看器差异可能导致测试误判。后续可学习 AbortController、状态机与故障注入测试。
