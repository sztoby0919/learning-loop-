# MoMA 真实接口验收

日期：2026-10-03（Asia/Shanghai）。用户明确授权真实调用，首次最多4次；实际首次3次，随后用户明确确认追加最多2次，实际共5次。不自动重试、不修改 `.env` 或用户配置、不创建用户课程、不写入真实学习证据、不上传教材。Key仅由进程按服务端同样方式加载用于鉴权，不打印或保存至报告。

## 当前配置及测试范围

- 配置解析为 `compatible`，不是 Mock。
- 基础地址 `https://zhenze-huhehaote.cmecloud.cn/v1`，实际 POST `/chat/completions`；测试限制为此地址，不跟随重定向。
- 请求模型 `deepseek-v4-flash-0731`，与用户提供的模型ID一致。连通测试响应的模型标签为 `deepseek-v4-flash`；它是服务返回的标签，不据此推断更具体版本。
- 连通测试使用无敏感文字，输出最多128tokens；业务请求沿用当前实际provider及草稿AI适配器的配置，max_tokens为4000。
- 出题内容仅是人为编写的训练集/测试集/过拟合三句说明；生成2道单选题，四选项与答案等字段通过项目现有校验。
- 诊断使用这两道真实生成的题，人为设置一次答错、一次答对，历史记录为空。这是测试作答，不是用户掌握情况。
- 草稿仅发送一个测试章节和约172字符的说明；章节ID、实际发送页码与建议字段经过项目现有校验，未应用到课程。
- 出题及诊断单次预算30秒，草稿90秒；没有自动重试，避免把直接provider的90秒等待当成网站30秒首尝试预算内成功。

## 保留失败证据

首次出题HTTP200，但测试脚本遇到 `Body is unusable: Body has already been read`；因此第一次出题不计通过，诊断未调用。该次脚本在返回响应前额外使用 `response.clone().json()`统计usage。

随后进行了两项不调用网络的检查：标准Response克隆后原响应仍可读取，且项目provider处理同结构离线响应成功。因此不能断言克隆必然有问题，也没有将该异常直接归为MoMA或产品根因。取消测试脚本额外读取响应的统计逻辑后，原有产品出题与诊断路径真实复验成功；这只证明此次复验通过，未完全解释首次响应体异常。没有修改产品provider或放宽校验。

首次三次请求的usage统计共1006tokens；追加两次未再次读取响应统计，故不报告五次总tokens或具体费用，实际以MoMA控制台为准。
