# 导入质量、可控 AI、草稿恢复与课程备份设计

日期：2026-10-01

状态：用户已确认设计并选择主代理在当前工作区逐项执行。第一、二批已实施并验收；2026-10-02 获准安装 yauzl 和类型声明。第三批 ZIP 及用户接受 Windows-only 边界的原生补充批次已完成；一次补充独立审查两项问题经作者失败复现与修复，最终494 passed/6 skipped、构建、三设备45/45（2worker）及441页教材通过。默认8worker偶发等待超时列为后续稳定性事项，不宣称全面安全审计或跨环境兼容。未 commit/push、未调用真实 API。

## 1. 目标与范围

服务现有 learning-loop 本地单用户项目，让用户能看清导入质量、控制 AI 修改、恢复未完成草稿，并安全备份及恢复课程。

已确认：五项优化全部纳入；草稿保留 7 天；恢复始终创建新课程、不覆盖原课程；保留现有 JSON 导出；不调用真实 MoMA、不提交或 push，除非用户另行授权。设计文档仅保存在工作区。

保持现有 Markdown 课程文件、learning-journal/ 自动发现及来源页链接。不会自动重写已有课程，不新增账号、多人系统、OCR、公式恢复、数据库、内置题库或“待核对”标识。

成功标准：用户可以完成“上传 → 看质量报告 → 编辑并恢复草稿 → 请求指定章节 AI 建议 → 比较并选择应用 → 建课 → ZIP 备份 → 预览恢复为新课程”的完整流程；失败不损坏原课程，不悄悄应用 AI 结果，不泄露密钥。

## 2. 技术路线与实施顺序

选择沿用本地文件，而不是引入数据库或独立任务服务：前者与课程存储和当前单用户用途一致，后两者增加部署及迁移成本，暂无必要。

拆成三个可独立验收的子项目：

1. 导入质量报告和草稿持久化：建立稳定草稿 ID、版本及恢复入口。
2. AI 建议对比、按章节应用、撤销、等待和取消：建立在版本化草稿之上。
3. ZIP 备份和恢复：独立服务模块，复用课程解析器、来源安全检查和登记逻辑。

每批单独完成回归测试和构建；最后进行整套验收及 README 更新。本文是统一行为契约，后续实施计划逐批列出文件与测试任务。

## 3. 现有代码与职责

- pdf-extractor.ts：逐页提取、旁注及复杂版面启发式检测，目前只输出汇总警告。
- course-import.ts：基础草稿和五个 Markdown 文件生成，附录 references 独立于 AI notes。
- course-import-manager.ts：草稿生命周期、编辑、AI 完善、确认；当前草稿仅驻留内存。

- workspace-repository.ts / app.ts：课程登记、Markdown JSON 导出与接口。

新逻辑按职责拆分为草稿存储、AI 建议操作、备份服务等小模块，不把所有实现堆入 app.ts，也不做无关重构。

## 4. 第一批：导入质量报告

### 数据与含义

在 ExtractedDocument 增加可选、版本化的结构化质量信息，保留现有 warnings 兼容其他格式及旧调用者：

- 无可提取文字的 PDF 物理页码。
- 检测到疑似旁注、已调整文本顺序的页码。
- 疑似分栏、表格、旋转或复杂排版的页码。

报告来自实际提取过程，不从自然语言警告反向解析，也不生成“准确率”“置信度百分比”。同一页允许属于多个分类。空白页和扫描页不能仅凭无文字检测区分，页面文案必须说明这一点。

### 交互

预览页显示分类数量，可展开分页/折叠的页码列表，避免长教材生成数百个常驻按钮。点击页码打开当前草稿原 PDF 的对应物理页（不是教材印刷页码）。未建课也能查看来源。

新增只读草稿来源接口，仅通过草稿 ID 和允许的受管 source 文件查找，不能接受任意磁盘路径。草稿失效、取消、来源文件缺失时明确报错。

Word、Markdown、HTML 继续显示现有格式提醒；没有可靠页码时不伪造 PDF 式质量报告。

### 验收

检测数据与真实页码一致；类别重叠正确；点击能打开上传文件；1,000 页报告不使页面横向溢出；来源路径越界及符号链接被拒绝；不发送文本到 API。

## 5. 第一批：草稿保存与恢复

### 存储

在 .learning-loop/imports/ 下使用独立草稿目录，保存原文件及版本化的内部状态快照。快照是内部存储数据，不修改用户课程配置、不改变 Markdown 课程格式，也不加入用户现有 JSON 导出。

状态包括草稿 ID、预分配课程 ID、格式与原文件名、创建时间、到期时间、修订号、用户编辑、提取结果、质量信息、附录元数据；后续包含 AI 候选建议及最近一次可撤销快照。不得保存 API Key、Authorization、环境变量或原始鉴权报错。

采用同目录临时文件写入后原子 rename，更新成功才替换内存状态。读入时校验 schema、ID、页码、类型、版本和文件路径，不信任快照里的绝对路径。快照损坏不阻断其他草稿列表，明确提示该草稿无法恢复，保留直到删除/到期而不生成课程。

### 自动保存与冲突

有效编辑在停顿约 800 毫秒后自动保存，页面展示“保存中 / 已保存 / 保存失败”。浏览器中的即时内容与服务端修订号分离；响应乱序不能覆盖新输入。无效的临时输入保留在当前编辑页并提示，但不写成不合法的服务端草稿。

每次更新携带 expectedRevision；与最新版本不同返回 409 并提供重新载入操作，不能静默覆盖另一个标签页的编辑。刷新时只能保证已显示“已保存”的编辑恢复，未完成保存的编辑通过离开提示告知风险。

预览更新、AI 请求和确认建课前等待当前有效编辑保存。来源资料和附录元数据由服务端维护，客户端编辑不能改写它们。

### 列表与生命周期

导入入口提供“继续草稿”列表，显示名称、保存时间及到期时间。页面 URL 带草稿 ID，刷新后重新读取；localStorage 最多保存导航偏好，不存教材正文。

到期时间固定为创建后 7 天，不因编辑无限延长。用户主动删除前确认；取消导入即删除草稿和上传副本，不影响已建课程。启动时及每小时只清理已验证位于受管草稿根目录内的到期文件，不跟随符号链接，不递归删除任意配置路径。

建课保留现有先暂存、再发布、再登记的原则。确认操作产生可恢复的状态记录：重复确认返回同一已创建课程结果或明确已提交提示，不生成第二门课程。启动恢复时协调草稿提交状态与已发布课程；确认失败允许重试，不删除成功课程。

旧内存草稿在服务升级后不能承诺恢复：旧格式遗留上传文件按原到期规则清理，不伪造丢失的编辑内容。现有课程保持不变。

### 验收

刷新、服务重启后编辑恢复；修订冲突不覆盖；写入失败不假报保存成功；损坏快照不影响健康草稿；7 天固定到期与删除正确；重复及中断确认不重复建课；使用临时目录测试，不动用户真实学习档案。

## 6. 第二批：AI 建议、对比和应用

### 章节选择与发送范围

所有编辑阶段具备稳定内部 ID，移动或改标题不改变 ID。基础阶段保留可追溯的来源章节及起始页信息。新加的手工阶段没有来源范围时明确提示，不能猜测页码；首版不提供 AI 完善该阶段的选项。

选择的来源章节范围从其起始页到下一个有效来源章节前一页；每章最多发送开头两页、每页最多 1,200 字符，全请求含选中目录及页码标记最多 24,000 字符。截断后只列实际发送的页面和字符数。范围跨越目录辅助页时不把辅助内容当作正文总结。

请求前提供“查看将发送的摘录”，显示实际章节、页面、文本以及课程名、目标和每周时间；只有明确同意并点击按钮才调用配置的服务。选择变化后需重新确认当前发送范围。未配置/Mock 模式保留基础建课，不假称真实 AI 完善。

### 候选建议

AI 仅对选中章节生成一对一建议：保留稳定阶段 ID，返回建议标题、任务及带发送范围内页码的笔记。拒绝额外章节、重复 ID、越界页码和非法字段；不把新增或未发送章节包装成已阅读内容。

服务端先存候选结果，而不改当前草稿。每章展示原内容与建议内容的对比，支持接受或拒绝。只接受的章节替换其阶段和关联笔记，其余章节和用户目标、学习时间、来源质量、附录元数据保持原样。附录链接始终由本地 references 生成，不由模型决定。

候选与请求开始时的修订号绑定。生成中冻结当前草稿修改；其他标签页造成修订变化时，候选失效，返回明确冲突提示，不强行应用。用户在候选生成后编辑相关草稿，也必须使旧候选失效。

### 撤销和来源

每次应用记录应用前快照及应用后修订号，仅保留最近一次撤销。撤销恢复应用前的阶段、笔记和 AI 状态，并保留来源信息；若应用后又发生编辑，禁止无提示地整份恢复旧内容，应明确提示该撤销已失效。

逐条笔记保留“原文摘录 / AI 归纳”的内部 provenance。混合应用后，未被替换的原文仍可核对为原文；AI 内容不能误标成直接摘录。不恢复“待核对”标识。旧课程缺少 provenance 时沿用保守来源判断。

### 等待、取消和重试

每份草稿同一时间只允许一个 AI 请求。生成时显示旋转图标和实际等待秒数，不显示虚假进度百分比。保留 90 秒超时，取消通过服务器 AbortController 传递给模型 fetch，而不是只关闭浏览器提示。

每次请求有唯一 operationId。取消先标记操作已取消再中止请求，任何迟到响应不能保存候选或修改草稿。取消、超时、鉴权、额度和格式错误分别显示可理解提示；用户可手动重试，默认不自动重试付费调用。取消不承诺模型提供商停止计费。

服务重启时未完成请求标记为已中断，保留已保存草稿，允许手动重试，绝不在启动时自动补发。建议应用不再次调用 API。

### 验收

请求前及未同意时零调用；只发送预览说明的内容；未选章节与附录不变；部分应用及撤销正确；乱序响应/取消/超时/重启/409 均不覆盖草稿；无效模型输出不能落盘；Mock 与可控假上游覆盖接口和浏览器流程，真实 MoMA 不在本次默认测试内。

## 7. 第三批：ZIP 备份与恢复

### 备份内容

设置页提供单课程及全部课程 ZIP 备份，保留现有 JSON 导出按钮和格式。归档采用固定相对路径和版本化 manifest：课程五个 Markdown、sessions/ 中的 Markdown、受管原课件（存在时），以及每个文件的字节数和 SHA-256。

仅打包明确允许的课程文件及通过现有 safeSourcePath 同级安全规则检查的原课件。拒绝符号链接、目录跳转和特殊文件；不沿着 Markdown 链接扫描磁盘，不打包 .env、配置文件、草稿、缓存或任意外部资源。

手工课程的可读取 Markdown 可以备份；没有受管原文件时，在 manifest 和下载前提示“未包含原课件/外部资源”，不能称为整个工作区的完整备份。用户主动写进 Markdown 的私人信息不会自动脱敏，下载前提示备份包含课程原文和学习记录。

### 限制与工具

首版归档限制：压缩文件不超过 250 MiB，声明及实际解压后总量不超过 500 MiB，最多 2,000 个文件、50 门课程。单个原文件维持已有格式上限（PDF 100、DOCX 50、HTML 20、文本 10 MiB）；单个 Markdown 状态/记录文件不超过 10 MiB。超过限制明确建议分课程备份。

不得只依赖 ZIP 内声明大小防止解压炸弹。实现需在实际解压过程中计数并在超限前终止；优先检查当前依赖是否具备有界解压能力，若不具备，先向用户说明所需新依赖并征求确认，不能用无界解压冒充安全验证，也不自动安装。

### 恢复预览

上传归档后先验证再展示课程名、文件数、原课件是否包含及限制提示，不自动发布课程。只接受本应用支持版本及允许路径的 ZIP；拒绝绝对路径、盘符、..、反斜杠路径歧义、重复条目、大小写冲突、链接、未知文件、错误 checksum、缺失核心 course.md 及不合法课程结构。

校验课程/课程关联 ID、五个文件与学习记录能被现有解析器读取。原文档是来源资产，不执行、不用来自动重新生成课程，也不发送 API。原课程使用失效外部资源路径时提示，不尝试读取恢复机外部磁盘。

### 确认恢复

所有恢复课程分配新 ID 和新目录，用户确认后才发布。通过结构化字段更新 course.md 的 id、其他档案 courseId、会话中已定义的课程关联 ID，以及资源中已知的本应用 /api/courses/<oldId>/source 来源链接；不全局字符串替换笔记内容、外部 URL 或普通引用文本。

学习记录、错题和复习证据原样保留，不能重算分数/日期或猜测缺失状态。重复确认只产生一次恢复结果；同名或同 ID 原课程从不覆盖。

先在 .learning-loop/ 下暂存和验证整批，再在发布锁下发布与登记；记录恢复事务以便启动后完成或回滚，不允许自动发现把未完成事务当作健康课程。失败时只清理该事务拥有的新目录，回滚新增登记，不删旧课程。登记完成后的监听失败沿用现有“课程已成功保存、可重新加载”的策略，不误删成功恢复。

### 验收

受管课件备份→新目录恢复→来源可打开→学习记录不变；单课程及整批均可用；手工课程缺原文件提示正确；同名恢复生成新课程；重复确认和中断恢复安全；损坏、checksum 错误、路径穿越、链接、大小写冲突、超大解压内容被拒绝；任何失败不覆盖旧数据；备份不包含密钥和外部文件。
