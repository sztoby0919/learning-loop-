# 学习闭环三阶段设计

日期：2026-09-28

## 目标与边界

按顺序交付：①错题本与针对性再练；②实际复习作答与下次计划；③导入课件的原文定位。每阶段都必须通过本阶段新增测试、现有完整测试和生产构建，失败时先修复再进入下一阶段。维持本地单用户、Markdown 档案、现有单选诊断和“作答后不可重选”的约定。不新增必需的 `mistakes.md` 或内置题库，也不把 Mock 成绩写成真实掌握证据。本轮不以真实 MoMA 调用为验收条件；这项外部联调仍需赛前单独完成。

现状：诊断确认后写入 `course.md`、`reviews.md`、`sessions/*.md`；复习页能显示提醒但不能完成复习；自动导入的笔记已有原始文件位置文字，却不能直接定位。未确认的诊断不会成为持久错题。

## 总体数据流与兼容性

`sessions/*.md` 是答题事件记录：诊断、针对性再练、复习作答分别使用可区分的 `kind` 和版本字段，正文保持人可读。新记录保存课程、题目、四个选项、所选选项、正确答案、知识点、解析、时间与 `real`/`mock` 来源；参考答案在提交前只存服务端。读取旧版诊断记录时尽力提取题干、选择、得分和解析；缺失的知识点标为“未标注”，不推断缺失字段。错误或未知格式的单个 session 只产生可见警告，不阻断整门课程。

`reviews.md` 继续是可编辑的计划摘要，实际作答证据留在 `sessions/`。新增写入使用现有原子写入与哈希冲突检测，保留用户手工编辑的其他行。读写只限定于已登记课程目录；现有用户课程和示例课程不做隐式迁移。服务重启后已保存记录仍可读取，未提交的内存题目会失效并提示重新生成。

## 阶段一：错题本与针对性再练

诊断经用户预览并确认写回后，错题本按课程展示答错的题目、所选答案、正确答案、解析、知识点、来源诊断日期与再练记录；未确认诊断不出现。旧版 session 可以只显示确实能解析的字段，不显示虚构的知识点。练习入口选择一条错题，调用现有 `AiProvider`，要求围绕同一知识点生成**不同于原题**的一道四选一单选题；服务端校验结构与题干差异，不合格时给出可重试错误，不暗中复用原题。

用户提交选项后，由服务端按隐藏的参考答案判分，只能查看解析，不能更换选项。用户明确确认保存后才新增练习 session；重复确认返回冲突而不重复写入。真实模型的已保存再练结果可显示为真实作答证据，但阶段一不据此改写 `reviews.md` 或提高掌握度。Mock 题目与结果始终有明显“离线演示”标记，可保存为带 `mock` 标识的练习记录以便回看，但不计入真实掌握统计。

## 阶段二：完成复习

复习页针对已登记的待复习知识点提供“开始复习”。沿用阶段一的出题、单次提交和解释组件，但题目以课程关键知识、知识点及可用的历史错误为上下文。只有真实模型作答且用户确认保存，才把复习 session 写入 `sessions/`，并更新 `reviews.md` 对应知识点的上次复习、下次复习与证据；更新过程整体原子化。若同名行有歧义、源文件被外部修改或课程不可写，保持原文件不变并明确报错。Mock 可以演示交互，但没有“完成真实复习”的效果，不推进日期或掌握度。

默认间隔沿用 1/3/7/30 天：答错后下次安排在 1 天后；答对后按已有真实复习记录推进到下一间隔，完成最后一档后维持 30 天。日期是**计划**而非完成证据。单道选择题的 0/100 分只写在复习 session 与证据文字中，不自动换算为整门课程或知识点的 1–10 掌握度；`reviews.md` 原有掌握度保持不变，空值继续为空。诊断创建的复习计划不得把诊断日期误写为“上次复习”。已有手工复习行保留，复习页与日历在保存后刷新；相同知识点的自动提醒不与手工行重复展示。

## 阶段三：原文定位

对由单文件导入生成的笔记和课程关键知识，展示“来源”卡片、位置及打开原文件入口。PDF 使用原始页码打开 `/api/courses/:id/source#page=N`；浏览器不支持页码锚点时仍可打开原 PDF。Word、HTML、Markdown/纯文本只有解析器产生的虚拟位置：展示“段文本/估算位置”，绝不标作真实页码。只有能与提取原文核对的短文本才称“原文摘录”；AI 完善的笔记内容与模型给出的页码均标为待核对，不冒充原文引用。无原文件的手工课程保持现有页面，不显示失效按钮。文件只经现有受控 source 路由读取，保留 HTML 沙箱响应头。

## 接口和页面边界

服务端提供按课程读取错题的接口，以及创建、作答、确认练习/复习的短生命周期接口。服务端负责身份为本地单用户的前提下校验课程、会话状态、选项与幂等；客户端只展示公开题目和状态。错题本可从课程详情进入；复习页增加动作列；导入课程的笔记与关键知识显示来源入口。页面的加载、超时、模型输出错误和文件冲突都要有可理解的提示，失败不落半成品记录。

## 验收与质量门槛

1. 阶段一：新旧诊断 session 解析、未确认不入错题本、不同题生成校验、单次提交、Mock 标记、确认保存与重复提交保护；接口测试和浏览器流程通过，再运行完整 `npm test` 与 `npm run build`。
2. 阶段二：真实/Mock 分流、答错重置与答对推进、诊断日期不冒充复习日期、手工行保留、哈希冲突与重复确认、重启后读取、复习页/日历刷新；接口测试和浏览器流程通过，再运行完整测试与构建。
3. 阶段三：PDF 真实页链接、非 PDF 虚拟位置标识、AI 引用待核对、无原文件时退化、路径安全与 HTML 沙箱；接口测试和浏览器流程通过，再运行完整测试与构建。

最终再运行全量浏览器测试。模拟模型只能证明流程与接口契约，不能证明真实 MoMA 的出题质量、时延或计费；正式参赛前需要另做真实接口验证。
