# Learning Loop

Learning Loop 把学习过程整理成可持续的反馈闭环：诊断目标、制定路线、主动回忆、实践、修复薄弱点，并把结果保存在 Markdown 学习档案中。本地 dashboard 支持从文档创建课程、查看学习统计和复习提醒，也可完成四选一单选诊断、预览修改并在确认后写回档案。每题提交后由服务端判分并显示解析，不能重新作答。

## 快速开始

需要 Node.js 20.19+（20.x）或 22.12+；建议使用 Node.js 22.12+ 的 LTS 版本。项目使用 Vite 8，不支持 Node.js 20.12 或 21.x。

```bash
git clone https://github.com/sztoby0919/learning-loop-.git
cd learning-loop-
npm ci
npm run build
npm run dashboard
```

打开 <http://127.0.0.1:3000>，默认会显示 `examples/demo-course`。

如果使用参赛提交 ZIP，进入解压后的“源代码”目录，从 `npm ci` 开始执行；完整步骤见外层的 `运行说明.md`。首次依赖安装需要网络，默认 Mock 运行无需模型凭证。

### 从文档创建课程

打开“课程”→“从文档创建课程”，选择或拖入一个或多个文件：

| 格式 | 支持内容 | 单文件上限 |
| --- | --- | --- |
| PDF | 可提取文字的课件或教材 | 100 MB、1,000 页 |
| Word `.docx` | 正文及标题结构，包括常见的中文“标题 1”等样式 | 50 MB |
| HTML `.html` / `.htm` | 正文及 `h1`–`h3` 标题 | 20 MB |
| Markdown `.md` / `.markdown`、纯文本 `.txt` | 正文及可识别的 Markdown 标题 | 10 MB |

多文件建课支持混合以上格式，每批最多 10 个文件、合计 200 MB。选择“当前课件”逐份编辑草稿或使用 AI 完善，点击“更新合并预览”保存整体课程名称并查看合并结果，最后确认创建一门课程。阶段按文件选择顺序合并，并带课件标识；同名文件各有独立来源。各课件编辑自动保存，整批草稿可通过网址或导入页的恢复入口继续，固定保留 7 天。

已有课程可在详情页点击“追加课件”，上传一份或多份文件，预览后确认追加。新增阶段、摘录、资源及原文明确日期会合并到当前课程，已有任务完成状态、个人笔记、学习记录、错题及复习数据保留。取消不修改课程；若预览期间课程文件被其他页面或程序修改，确认会拒绝覆盖，请重新核对后发起追加。一门课程最多保存 100 份来源文件。

非 PDF 文件最多处理约 1,000 页等价的文本长度；页面展示的“段文本”不是原文件的真实页码。网站先在本地提取内容并生成课程草稿，随后可修改课程名、学习目标、每周学习时间、阶段顺序及任务。有效编辑停顿约 800 毫秒后自动保存，只有显示“已保存”的内容承诺刷新及服务重启后恢复；尚未保存时刷新、关闭页面、站内跳转或浏览器前进/后退会提示风险。网址中的草稿 ID 和导入页的“继续已保存的草稿”入口可恢复编辑。每份草稿自上传起固定保留 7 天，修改不延长有效期；删除前需确认。多标签页修订冲突不会自动覆盖，可确认丢弃本地编辑后重新加载。保存失败保留当前输入，可主动重试。点击“更新预览”可检查即将写入的文件；点击“确认创建课程”会等待保存，重复确认不会重复建课。创建后立即跳转到新课程，课程列表无需重启即可看到。上传时显示进度，失败后可重试，取消则不会建课。

建课中断后，启动会恢复可信事务。若某个事务的草稿快照缺失、损坏或已发布文件无法验证，只隔离该事务，不影响健康课程与草稿；失败原因显示在草稿列表及服务终端，未决课程不自动登记。恢复数据不会被到期清理或普通删除草稿操作移除，应先备份后处理；这不是自动修复损坏文件。

PDF 草稿提供提取质量报告，分别列出无可提取文字、疑似旁注和复杂排版的物理页码，每组最多显示 50 个页码，可以在建课前打开原页。类别可以重叠；无文字页可能是空白、图片或扫描内容，并不等同于已识别为扫描版，也不代表 OCR 或准确率评估。Word 和文本不伪造 PDF 质量报告。

新课程保存在项目根目录 `learning-journal/<课程 ID>/`，包含 `course.md`、`notes.md`、`reviews.md`、`resources.md`、`schedule.md`、空的 `sessions/` 以及原始文档。单文件流程沿用 `source.<扩展名>`；多文件与追加课件使用 `source-<来源 ID>.<扩展名>`，避免同名文件覆盖。原始文档自动列入“资源”，可从资源页打开。每份 PDF 的页码指向自己的原文件，不因合并重新编号。手工配置的课程与自动导入的课程分开管理。

导入课程的“关键知识”和“笔记”会在可定位的标题下显示“来源”卡片。只有受管理的原文件仍存在且来源标记有效时，才会出现“打开原文件”。PDF 链接带真实页码 `#page=N`；浏览器不支持页码锚点时仍可打开 PDF。Word、HTML、Markdown 和纯文本显示的是解析器生成的“第 N 段文本（估算位置）”，不是原文件页码。来源链接只代表可打开文件；仅当显示“原文摘录”时，摘录文本才已与提取内容核对。AI 完善内容不自动显示为“原文摘录”，仍需自己对照原文件检查；无原文件的手工课程不显示来源按钮。

PDF 章节识别优先使用书签目录（包括嵌套目录），没有可用书签时参考页首附近的编号标题和明显大于正文的短标题。若仍无可用章节，自动按页码生成基础学习阶段：通常每 5 页一段，长文档适当扩大分段以限制在 60 个阶段以内；纯空白分段跳过，来源从可提取正文的页码开始。这些阅读分段不代表原书章节，但同样可以预览摘录并进行 AI 完善。已有旧版草稿不会自动改写；需要重新导入 PDF 才会应用新识别规则。此功能不包含 OCR，纯扫描版仍需先转换为可提取文字的 PDF。

“AI 完善草稿”是可选步骤。先选择有来源范围的章节或页码分段，点击“查看将发送的摘录”，查看实际目录、页码、正文、字符数，以及课程名称、目标和每周时间；改变选择或编辑后需要重新查看并同意。仅所选章节开头最多两页、每页最多 1,200 字符，实际总发送量不超过 24,000 字符，不发送完整文档。没有来源范围的手工阶段不能 AI 完善。未勾选同意或未点击完善按钮时不会调用模型；未配置 API、Mock 或调用失败时仍可创建基础课程。AI 返回独立候选，显示原草稿与建议对比；只有勾选接受并点击应用的章节才会替换，其他章节及附录保留原样，未接受的候选丢弃。可撤销最近一次应用，后续编辑会使撤销失效，避免覆盖新输入。新课程逐条区分原文摘录与 AI 归纳，原文仍需与来源实际内容匹配才能显示已核验摘录。

AI 运行时显示转圈和实际等待秒数。AI 完善、诊断和练习共用统一的 90 秒请求期限；暂时网络故障或 HTTP 500/502/503/504 最多自动重试一次，等待、重试和读取响应均计入该次操作总期限，可能增加调用费用。超时、鉴权失败、额度不足和格式错误不会自动重试；超时会中止本地底层请求并显示具体提示。AI 完善可主动取消；中止或取消不保证模型提供商停止计费。每份草稿同时只有一个操作，生成中不能编辑或建课；刷新后只读取已有操作，不因刷新重发付费请求。取消后的迟到响应不会保存候选。服务重启后未完成操作标为已中断，允许主动重试，绝不自动补发。失败保留原草稿，不编造诊断分数或学习证据。AI 对长教材只生成章节级起点，不保证逐页覆盖；请对照原文核查公式、表格、图片及笔记。扫描版和加密 PDF 暂不支持。没有学习证据的掌握度不会自动填写；日程只提取原文中明确写出的日期。

PDF 基础草稿默认不把目录、前言、符号表列为学习阶段；附录保留为参考摘录及带页码的资源链接。文字提取结合坐标整理文本行、保留段落间隔，并把有明确几何特征的小字号旁注放到该页正文之后；复杂分栏、旋转文本或表格只能保守处理并提示，不能保证阅读顺序准确。新生成的 PDF 摘录以纯文本块保留换行，避免把错乱公式、表格或原文 Markdown 符号渲染成看似可靠的结构；来源链接仍可打开原页，旧课程保持兼容。这不是 OCR，也不会修复原文字层已有的识别错误。AI 完善的提示词要求不推测补全损坏的公式或表格关系，但不能代替人工核对。以上优化只影响新导入的课程，不重写已有学习档案。

### 编辑与删除已创建课程

课程详情页提供“编辑课程”和“删除课程”。编辑支持名称、简介、学习阶段、任务及完成状态，点击“保存课程”后写入本地档案；取消和离开未保存表单时会提示。保存前检查文件版本，外部修改冲突会保留当前输入并拒绝覆盖，请重新打开编辑后合并修改。

删除需确认，从应用中移除课程并在 `course.md` frontmatter 写入 `deleted: true`；本地课件、笔记、错题与学习记录保留，重启不会重新显示。当前未提供恢复按钮，如需恢复，备份后移除 `deleted`、`deletedAt` 字段并重启服务。编辑时原任务文字未变的来源链接会保留；改写任务文字后请核对相关来源。路线中的非任务说明保留在路线末尾。

### 学习统计、复习与导出

- “统计”根据已有学习记录显示每周活动、连续学习天数、课程进度和待处理复习；没有记录时不会伪造数据。
- 学习记录会生成第 1、3、7、30 天的计划复习提醒，并显示在“复习”和“日历”。提醒只是计划，不代表已经完成复习；未记录证据时会明确标注，逾期提醒不会自动跳过。已有手工复习计划时优先使用手工记录。
- “设置”可切换深色模式，选择保存在当前浏览器的 `localStorage`。同页的“导出全部数据”仍下载原格式 JSON，包含已登记课程的 Markdown 文件和学习记录，但**不包含**原始 PDF、Word 等课件；JSON 不是可恢复的完整备份。单课程也保留 JSON 导出接口。

### ZIP 备份与恢复

交付状态：原生目录句柄绑定已接入全部 ZIP 文件操作。Windows 使用系统 PowerShell/.NET 辅助程序，**已完成约定的本机 Windows 单服务验收**；macOS 使用项目内的 POSIX 辅助进程，已完成本机单服务验收（见 `docs/superpowers/reports/2026-10-09-posix-native-file-io.md`）。一次独立审查发现的原位链接窗口和提交失败释放问题已由作者以失败复现→修复→完整回归验证，不宣称全面安全审计或所有系统环境兼容。内部计划和验收记录仅保存在本地，不随仓库发布。

ZIP 功能面向本地单服务实例：Windows 10/11 需要系统 Windows PowerShell/.NET 可运行项目内固定的辅助程序，macOS 与 Linux 由 Node 运行同目录下的 POSIX 辅助进程；不会安装工具链、提升权限或修改执行策略。两个辅助程序都不接受网络共享路径（UNC）、目录链接、符号链接或多硬链接文件，也都只接受规范绝对路径：请把工作区放在不含符号链接的路径下（macOS 的系统临时目录经 `/var` 链接，本机验收脚本会先做 realpath）。辅助程序不可用、被系统策略禁止、异常退出，或当前文件系统不支持按对象标识寻址时，ZIP 明确报错并停止，不回退到普通路径读写；健康手工课程、普通文档导入及 AI 功能仍可使用。此时自动发现的 `restored-` 课程可能暂不展示，但原目录不会被删除；恢复环境并检查事务记录后重启服务。更新后请重启服务，仅刷新网页不能更新服务端代码。

在“设置 → ZIP 备份与恢复”选择单门或全部课程，先预览每门是否包含原课件，再确认下载。ZIP 保存课程五个 Markdown、`sessions/` 的 Markdown、存在且受管的 `source.*` 或 `source-<来源 ID>.*` 原课件，以及版本、文件长度和 SHA-256 校验信息。多文件课程的所有受管课件及对应来源关系一起保存，恢复为新课程后来源链接同步更新。它**不是整个工作区备份**：不会包含 `.env`、API Key 配置、草稿、缓存、独立笔记、浏览器偏好或任意外部资源，也不会沿笔记链接读取磁盘。手工课程未包含受管原课件时会明确提醒。

备份中的笔记、课件和学习记录可能包含私人信息，不会自动脱敏；请妥善保管 ZIP。备份和恢复不调用模型 API。编辑文件期间无法取得一致快照时会拒绝本次下载，请停止编辑后手动重试。

恢复只接受本应用版本 1 的 ZIP：上传后先检查路径、重复条目、实际大小、文件哈希及课程格式，展示课程清单；点击“确认恢复为新课程”才发布。每门生成新 ID、新目录，**不覆盖原课程**；原课件字节、日期、分数及错题关联保留，内部来源链接更新到新课程。取消恢复不建课。预览链接支持刷新或服务重启继续，固定创建后 **24 小时**到期，启动及每小时清理；同期间重复确认返回同一结果，不重复建课。

限制：ZIP ≤250 MiB、实际解压总量 ≤500 MiB、≤2,000 文件、≤50 门课程；单 Markdown ≤10 MiB，来源 PDF ≤100 / DOCX ≤50 / HTML ≤20 / 文本 ≤10 MiB。超限请分课程备份。拒绝损坏归档、加密 ZIP、未知路径、盘符/路径穿越、大小写冲突、链接及校验不一致文件。恢复暂存在 `.learning-loop/restores/`；整批发布中断会在启动发现课程之前回滚。事务记录损坏时保留数据并停止相关恢复，不猜测归属或删除原课程；请先备份本地目录再检查终端提示。仅支持本地**单服务实例**，不要让两个服务同时共享该目录。

### 从错题到下一次复习

1. 完成诊断并确认写回后，在课程详情进入“查看错题本”。错题本展示已保存的错误、解析与来源记录；未确认的诊断不会进入。选择一道错题可生成同知识点的另一道四选一题，提交后查看判分与解析，再确认保存作答。再练记录不会自动提高掌握度或改写复习计划。
2. 在“复习”页对待复习知识点点击“开始复习”，完成作答并确认保存。只有真实模型模式的已确认复习才写入实际复习证据并推进下一次日期；答错后安排 1 天，答对后按 1、3、7、30 天间隔推进。日期只是计划，单题得分也不会自动换算为课程掌握度。Mock 模式可演示和保存带 `mock` 标记的作答，但不推进复习日期或掌握度。
3. 阅读导入课程的笔记或关键知识时，用“来源”卡片打开原课件核对内容。AI 生成内容、没有显示已核验摘录的内容和非 PDF 估算位置都需人工检查。

未填写任何模型参数时，诊断会使用离线 Mock 模式，适合演示交互，但不能代表真实模型的诊断质量。使用移动云 MOMA 或其他 OpenAI 兼容的文本 Chat Completions API 时，将 `.env.example` 复制为项目根目录的 `.env`，填写 `AI_BASE_URL`（基础地址，通常包含 `/v1`，不要包含 `/chat/completions`）、`AI_API_KEY` 和 `AI_MODEL`，再重启服务。三项必须一起填写；部分填写或保留示例值会在启动时提示配置错误，不会悄悄进入 Mock。需要暂时离线演示时可设置 `AI_MODE=mock`。`.env` 已被 Git 忽略；不要把密钥提交到仓库或发送到聊天中。课程材料和作答会发送给所配置的模型服务，请勿直接使用敏感资料。

常用命令：

```bash
npm run dashboard:dev   # Vite + Express 开发模式
npm test                # 单元、接口及测试服务隔离验证
npm run build           # 类型检查和生产构建
npm run test:e2e        # Playwright 浏览器测试
```

浏览器测试在 `127.0.0.1:4274` 启动自己的 Mock 服务，结束后由 Playwright 关闭，不复用已有服务。如果该端口已占用，测试会报错；请先确认占用进程，再关闭该进程，勿把旧服务的响应当作本次测试结果。

需要隔离端口时可设置 `LEARNING_LOOP_E2E_PORT`（1–65535）。测试服务隔离的回归测试会使用独立临时端口，不占用你正在运行的开发服务。

长 PDF 的本地验收（不调用 AI、不写入项目课程目录）：

```bash
cd dashboard
node --import tsx/esm scripts/benchmark-pdf-import.mjs
node --import tsx/esm scripts/benchmark-pdf-import.mjs "/path/to/textbook.pdf"
```

不传路径时使用 1,000 页合成样本；传入路径时使用自己的文字版 PDF。输出文件大小、页数、耗时、采样到的进程内存、预览文件一致性及重新从磁盘发现课程的结果。合成样本不代表真实教材、复杂公式或表格的提取质量；真实教材仍需人工对照原文检查。

## 使用 `$learning-loop`

根目录本身就是一个可安装的 Codex skill，直接包含 `SKILL.md` 和 `agents/openai.yaml`。将仓库根目录安装为名为 `learning-loop` 的 skill 后，在 Codex 中调用：

```text
$learning-loop 帮我系统学习一个新主题，并维护学习档案
```

skill 会在当前学习项目中维护 `learning-journal/<topic>/`。然后复制下面的本地配置示例，并把 `courses[].root` 指向需要展示的课程目录：

```json
{
  "courses": [
    { "root": "../my-study/learning-journal/my-topic", "enabled": true }
  ]
}
```

配置文件相对于配置文件自身所在目录解析。个人配置可以命名为 `dashboard.config.local.json`，该文件已被 Git 忽略；也可以显式指定：

```bash
npm run dashboard -- --config /path/to/dashboard.config.json
```

Windows PowerShell 示例：

```powershell
npm run dashboard -- --config C:\path\to\dashboard.config.json
```

## 不使用 Codex

复制 `templates/course`，将它改成自己的主题目录，把其中的 `YYYY-MM-DD` 换成实际日期，再在 dashboard 配置中登记。第一版支持标准 Markdown 档案：

- `course.md`：概览、学习路线、关键知识、易错点、学习记录；
- `notes.md`：笔记；
- `reviews.md`：复习计划；
- `resources.md`：学习资源；
- `schedule.md`：日程；
- `sessions/`：可选的学习过程记录。

网站读取这些文件，文件保存后通过 SSE 自动刷新。诊断写回仅在用户预览并确认后进行，使用文件哈希检查避免覆盖预览后发生的外部修改。没有证据的完成度、掌握度和日期保持为空，不会被网站虚构。

## 项目边界

这是一个本地优先项目：档案存放在本地，不需要账号或数据库。离线 Mock 模式不会调用外部模型；配置真实模型后，诊断所需的课程片段和作答会发送到模型 API。当前只实现 OpenAI 兼容的文本 Chat Completions 协议，不支持 Anthropic Messages、Gemini 原生协议或多模态接口。移动云 MoMA 的本机历史验收见 `docs/superpowers/reports/2026-10-03-moma-live-acceptance.md`，历史通过不保证接口持续可用。PDF 导入只提取文字层，不做扫描图片 OCR；HTML 导入只提取正文与标题，不抓取外部网页。导入草稿和上传副本保存在 `.learning-loop/imports/`，启动及每小时清理到期草稿，不包含在现有 JSON 导出中。ZIP 备份恢复用于本地单服务实例，可把课程和来源恢复为新课程；支持 Windows 10/11 与 macOS，Linux 已实现但未在真机验收。旧版本仅驻留内存的草稿不能恢复。服务重启后，未确认的诊断会话仍会失效。`$learning-loop` 可用于创建和维护学习档案。
